One-click production platform in AWS CDKPlataforma de producción "one-click" en AWS CDK

An insurer selling policies through a bank's channels needed a production environment that passes a bank's security review, and the same setup for Dev, QA and UAT. I wrote it as one CDK app: change a few values and the whole platform deploys.

Una aseguradora que vende pólizas por los canales de un banco necesitaba un ambiente productivo que pase la revisión de seguridad del banco, y el mismo esquema para Dev, QA y UAT. Lo escribí como una sola app CDK: cambias unos valores y se despliega toda la plataforma.

  • Network and data: app VPC and database VPC over peering, DocumentDB 5.0 encrypted with KMS, and separate database users for ECS and Lambda with secrets rotated every 30 days.
  • Compute: ECS Fargate services behind a public and an internal ALB, with autoscaling on CPU, memory and a day/night schedule, plus Container Insights.
  • Edge security: four WAF Web ACLs with 62 rules (CloudFront, public ALB, internal ALB, API) with AWS managed rule groups, Bot Control, anti-DDoS, geo blocking, host allow lists and IP sets.
  • API: HTTP API Gateway with a Lambda authorizer reaching the internal ALB over a VPC Link; CloudFront signs requests with a header secret so the API only accepts traffic from the CDN.
  • Resilience and audit: AWS Backup with daily, weekly and monthly rules (5-year retention) copied to a second region, S3 cross-region replication to Glacier, and CloudTrail data events on S3 and Lambda.
  • Red y datos: VPC de aplicación y VPC de base de datos por peering, DocumentDB 5.0 cifrado con KMS y usuarios de base separados para ECS y Lambda con secretos rotados cada 30 días.
  • Cómputo: servicios ECS Fargate detrás de un ALB público y uno interno, con autoscaling por CPU, memoria y horario día/noche, más Container Insights.
  • Seguridad perimetral: cuatro Web ACL de WAF con 62 reglas (CloudFront, ALB público, ALB interno, API) con reglas administradas de AWS, Bot Control, anti-DDoS, bloqueo por país, hosts permitidos e IP sets.
  • API: HTTP API Gateway con autorizador Lambda que llega al ALB interno por VPC Link; CloudFront firma las peticiones con un header secreto para que la API solo acepte tráfico del CDN.
  • Resiliencia y auditoría: AWS Backup con reglas diaria, semanal y mensual (retención de 5 años) copiadas a otra región, replicación S3 cross-region a Glacier y CloudTrail con eventos de datos en S3 y Lambda.

Organization-wide cost optimization on Google CloudOptimización de costos de toda una organización en Google Cloud

Cost recommendations were scattered across many projects, each visible only in its own console page, and managers had no way to see the total or prioritize it without GCP access.

Las recomendaciones de costo estaban dispersas en muchos proyectos, cada una visible solo en su propia consola, y los gerentes no tenían forma de ver el total ni priorizarlo sin acceso a GCP.

  • Analyzed three months of billing and found Compute Engine drove about 78% of spend, mostly oversized autoscaled GKE node pools running at low utilization.
  • Built a read-only Python toolkit: Cloud Asset Inventory discovers every project, the Recommender API is queried per project and zone, and the results become a self-contained HTML report managers open in any browser.
  • Covered VM and GKE node-pool rightsizing, idle VMs, unattached disks and unused external IPs, grouped by project and estimated monthly savings.
  • Executed 18 optimization actions and left a roadmap: flexible Committed Use Discounts, moving N1 machines to newer families, cutting inter-zone egress and reviewing licensing costs.
  • Analicé tres meses de facturación y encontré que Compute Engine representaba cerca del 78% del gasto, sobre todo por node pools de GKE sobredimensionados con baja utilización.
  • Construí un toolkit en Python de solo lectura: Cloud Asset Inventory descubre cada proyecto, se consulta la Recommender API por proyecto y zona, y los resultados se convierten en un reporte HTML autocontenido que los gerentes abren en cualquier navegador.
  • Cubre rightsizing de VMs y node pools de GKE, VMs inactivas, discos sin usar e IPs externas sin uso, agrupados por proyecto y ahorro mensual estimado.
  • Ejecuté 18 acciones de optimización y dejé un roadmap: Committed Use Discounts flexibles, migrar máquinas N1 a familias nuevas, reducir el tráfico entre zonas y revisar costos de licencias.
~78%of spend traced to Compute Enginedel gasto en Compute Engine 18actions executedacciones ejecutadas 5recommender typestipos de recomendación

What I learned the hard way: GKE node pools use a different recommender than standalone VMs, so querying only the VM recommender hides the biggest cost driver; and the Recommender API returns an empty list both for "no findings" and "no permission", so verbose logging is the only way to tell them apart.

Lo que aprendí en la práctica: los node pools de GKE usan un recommender distinto al de las VMs, así que consultar solo el de VMs oculta el mayor generador de costo; y la Recommender API devuelve una lista vacía tanto si no hay hallazgos como si faltan permisos, por lo que solo un log detallado permite distinguirlos.

Event-driven backbone with failure isolation and log analyticsColumna vertebral orientada a eventos, con aislamiento de fallos y analítica de logs

A platform mixing a monolith and microservices on ECS needed asynchronous work (notifications, long-running tasks) that would not take the system down when one message failed, plus a cheap way to investigate security traffic.

Una plataforma que combinaba un monolito y microservicios en ECS necesitaba trabajo asíncrono (notificaciones, tareas largas) que no tumbara el sistema cuando un mensaje fallaba, y una forma económica de investigar el tráfico de seguridad.

  • CloudFront and WAF in front of both API Gateway and the ECS monolith; behind the API, EventBridge routes events to microservices, Step Functions orchestrates multi-step tasks and SQS buffers notifications.
  • Malformed SMS messages were retried endlessly and saturated the SMS gateways. I added a dead-letter queue in CDK (3 receives, 14-day retention, alerts), which isolated poison messages and kept notifications flowing.
  • WAF logs land in an encrypted, private S3 bucket and are queried with Athena using partition projection, so new hourly partitions need no MSCK REPAIR. Investigations such as "top blocked IPs by country this week" went from minutes to seconds and scan far less data.
  • CloudFront y WAF delante de API Gateway y del monolito en ECS; detrás de la API, EventBridge enruta eventos a microservicios, Step Functions orquesta tareas de varios pasos y SQS amortigua las notificaciones.
  • Los mensajes SMS defectuosos se reintentaban sin fin y saturaban las pasarelas de SMS. Agregué una dead-letter queue en CDK (3 recepciones, 14 días de retención, alertas), que aisló los mensajes envenenados y mantuvo fluyendo las notificaciones.
  • Los logs de WAF llegan a un bucket S3 privado y cifrado, y se consultan con Athena usando partition projection, así las particiones por hora no necesitan MSCK REPAIR. Investigaciones como "IPs más bloqueadas por país esta semana" pasaron de minutos a segundos y escanean mucho menos datos.
